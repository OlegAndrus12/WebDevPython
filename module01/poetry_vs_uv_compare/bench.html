Резолюція

Перетворити діапазони з маніфесту на точні версії у lock-файлі.

шкала обох панелей спільна, 0 – 8.91 с

У pip lock-файлів немає — у цьому рядку працює pip-compile з pip-tools, окремого проєкту. Це найближчий аналог, а не сам pip.

Встановлення, порожній кеш

Перший раз на новій машині або в CI без кешу: створити venv і завантажити всі пакети.

шкала обох панелей спільна, 0 – 34.3 с

Єдиний сценарій, який залежить від мережі, а не від інструмента: усі три чекають на ті самі wheel-и з PyPI. Тому саме тут різниця між двома запусками того самого інструмента може бути більшою, ніж різниця між інструментами — не робіть із цих цифр висновків про резолвери. На цій машині uv тут не найшвидший — перемагає Poetry.

Встановлення, теплий кеш

Друге оточення з тими самими залежностями — пакети вже в кеші, лишається розпакувати їх у venv.

шкала обох панелей спільна, 0 – 22.4 с

Тут видно ціну копіювання файлів: uv кладе у venv жорсткі посилання на глобальний кеш замість копій, тому «встановлення» — це майже лише створення записів у теці. Це сценарій, який ви проходите щодня.

Як це міряли

  • Кеші перенаправлені, а не почищені. Кожен процес отримує PIP_CACHE_DIR, POETRY_CACHE_DIR, UV_CACHE_DIR у тимчасовій теці. «Порожній кеш» — це новий порожній кеш, а не uv cache clean: ваш справжній кеш не чіпають.
  • Один інтерпретатор на всі три інструменти, знайдений через uv python find. Жодному з них не дозволено завантажувати Python, інакше ми міряли б швидкість мережі, а не резолвер.
  • venv створюється всередині заміру. poetry install і uv sync роблять оточення самі, тому pip міряється разом із python -m venv — інакше pip виглядав би швидшим, ніж він є.
  • Міряється лише команда під тестом. Lock-файл, з якого встановлюють, і прогрів кешу — це підготовка, вона поза таймером.
  • pip встановлює з приколотих версій. У рядку «резолюція» він справді резолвить (через pip-compile), а в рядках встановлення читає готовий requirements.txt — так само, як Poetry й uv читають свої lock-файли. Реальний requirements.txt теж приколотий, тому pip там швидший саме тому, що робить менше.
  • Один запуск на клітинку — це заміри, а не статистика. Для «резолюції» й «теплого кешу» різниця між запусками — одиниці відсотків; для «порожнього кешу» вона велика. Кожна команда, її тривалість і код повернення — у results.json.
