# module06 — Flask + SQLAlchemy + Alembic + Postgres

A news reader on [newsapi.org](https://newsapi.org/). The front page asks
NewsAPI for stories, stores them in Postgres and renders them; every other route
reads the database only. Two tables, six routes, every query in one file.

```
cnn-website/
  cnn_website/
    views.py          the Flask app object and all six routes
    repository.py     every query in the project
    models.py         Source and Article
    db.py             engine, sessionmaker, get_session()
    news_api.py       the NewsAPI client (requests)
    settings.py       pydantic-settings, validated at import
    utils.py          article_json, int_arg, domain, slugify
    templates/        base, index, article, _card
  migrations/         Alembic: env.py + two revisions
  docker-compose.yaml db + api + pgAdmin
```

**Stack:** Flask 3.1 · SQLAlchemy 2.0 (sync) · Alembic 1.19 · psycopg 3 ·
requests · pydantic-settings · Postgres 15 · Python 3.13 · uv

## Running it

Get a free key at <https://newsapi.org/register> — 100 requests a day, and `/`
spends one per load.

```bash
cd module06/cnn-website
cp .env.example .env          # then put your key in NEWS_API_KEY
docker compose up --build --wait
```

`--wait` blocks until every healthcheck passes, so a `curl` can be chained after
it. Migrations run on container start (`uv sync && alembic upgrade head &&
flask run`).

| service | container | URL | |
| --- | --- | --- | --- |
| `api` | `cnn06_api` | <http://localhost:8006> | the reader |
| `db` | `cnn06_postgres` | `localhost:5406` | Postgres 15 (`5432` in-network) |
| `pgadmin` | `cnn06_pgadmin` | <http://localhost:5106> | `admin@gmail.com` / `admin`, `db` preloaded |

Every published port ends in **06**, the module number, so modules 06–11 can all
run at once. `name: cnn06` in `docker-compose.yaml` is load-bearing: without it
Compose derives the project name from the directory, which is `cnn-website` in
six sibling projects.

### Or run Flask on the host

```bash
docker compose up -d --wait db                 # just Postgres, on localhost:5406
uv run alembic upgrade head
uv run flask --app cnn_website run --debug     # -> http://localhost:5000
```

The `.env` defaults describe this case; the container overrides `DB_HOST`/`DB_PORT`
to `db:5432`.

### Everyday commands

```bash
docker compose logs -f api                      # follow the app log
docker compose exec db psql -U admin -d cnn     # a psql prompt
docker compose exec api alembic current         # which revision it is on
docker compose down                             # stop; keeps the volume
docker compose down -v                          # stop and delete the database
```

## What this module covers

**Flask as the web layer.** One module-level `app` in `views.py` with the routes
beside it, re-exported from `__init__.py` so `flask --app cnn_website run` and
`gunicorn cnn_website:app` both resolve. No `create_app()` factory on purpose:
what a factory buys is a second app with different config, and that comes from
the environment here instead.

**Templates and one filter.** `base.html` inheritance, a shared `_card.html`
partial used by both the grid and the lead story, and one filter registered with
`app.add_template_filter(domain, "domain")` so `{{ article.url | domain }}`
renders `edition.cnn.com`.

**A session per unit of work.** `db.py` builds the engine and sessionmaker at
import, then hands out sessions through a `@contextmanager` that commits on a
clean exit, rolls back on an exception and always closes. The transaction
boundary is visible in the route body as `with get_session() as session:`.

**The repository pattern.** Every `select()` lives in `repository.py`; `views.py`
contains no SQL at all — `grep -rn "select(" cnn_website/` only ever hits the one
file.

**Upsert on a natural key.** NewsAPI issues no stable article id, so
`articles.url` is `UNIQUE` and `save_article()` looks a row up by URL before
choosing insert or update. Without that, every refresh would duplicate the whole
front page. Sources work the same way on `sources.slug`.

**Eager loading as a performance choice.** Both read queries state
`joinedload(Article.source)`. Drop it and the code still works — it just issues
one extra query per row, the classic N+1, invisible until you profile.

**Alembic owns the schema.** No `create_all()` anywhere. `alembic.ini` leaves
`sqlalchemy.url` empty and `migrations/env.py` fills it from
`settings.database_url`, so app and migrations cannot drift onto different
databases and no password lands in a file that goes into git. A naming
convention on `Base.metadata` gives constraints predictable names — otherwise an
autogenerated downgrade emits `drop_constraint(None, ...)`.

**Hand-written validation and serialisation.** `int_arg()` returns a bounded int
or raises with a message for the response body, so `per_page=-5` is a `400`
rather than a silent default. `article_json()` spells out every field including
`published_at.isoformat()`, since Flask's JSON provider would render an
HTTP-date. Both are exactly the work module07 hands to the framework.

**Settings as a validated object.** A missing `NEWS_API_KEY` fails at import
rather than becoming a NewsAPI 401 ten seconds later, and `SecretStr` keeps the
token out of tracebacks. The connection is stored in pieces because Compose needs
them split anyway; `database_url` is a `@computed_field` that assembles them,
running the password through `quote_plus`.

**Compose with real healthchecks.** Postgres accepts TCP connections seconds
before it accepts queries, so `depends_on: condition: service_healthy` only means
something because `db` has a `pg_isready` healthcheck. The Dockerfile puts the
venv at `/opt/venv`, outside `/app`, so the source bind mount cannot shadow it.

## Endpoints

| method | path | what it does |
| --- | --- | --- |
| `GET` | `/` | headlines, or `?q=` search — the only route that calls NewsAPI |
| `GET` | `/article/<id>` | detail page, rendered from the database |
| `GET` | `/api/articles` | stored articles as JSON: `?q=`, `?page=`, `?per_page=` |
| `GET` | `/api/articles/<id>` | one stored article as JSON |
| `GET` | `/api/stats` | how many stored articles each source accounts for |
| `GET` | `/healthz` | `SELECT 1`, used by the Compose healthcheck |

- `?q=` on `/` searches **NewsAPI**; `?q=` on `/api/articles` searches **what is
  already stored**.
- `/article/<id>` 404s with Flask's HTML page; `/api/articles/<id>` 404s with a
  JSON body, because a client parsing JSON should not be handed HTML.
- Only `/` spends quota, so the JSON API keeps working once it is exhausted.

```bash
B=localhost:8006
curl -s $B/healthz                                  # {"status":"ok"}
curl -s -o /dev/null -w '%{http_code}\n' $B/        # 200 -- fills the database
curl -s $B/api/stats
curl -s "$B/api/articles?per_page=1" | python3 -m json.tool
curl -s "$B/api/articles?q=trump&per_page=3"        # searches storage, not NewsAPI

curl -s -w ' [%{http_code}]\n' "$B/api/articles?page=0"
# {"error":"page must be at least 1, got 0"} [400]
curl -s -w ' [%{http_code}]\n' $B/api/articles/99999
# {"error":"article not found","id":99999} [404]
```

## Configuration

Environment first, then `.env` — which is how Compose overrides the database host
without editing a file.

| variable | default | what it is |
| --- | --- | --- |
| `NEWS_API_KEY` | *required* | no default; the app refuses to start without it |
| `DB_USER` / `DB_PASSWORD` / `DB_NAME` | `admin` / `admin` / `cnn` | also fed to Postgres by Compose |
| `DB_HOST` / `DB_PORT` | `localhost` / `5406` | the api container overrides both to `db:5432` |
| `DEFAULT_SOURCE` | `cnn` | which NewsAPI source the front page shows |
| `PAGE_SIZE` | `12` | how many articles to request **from NewsAPI** |
| `SECRET_KEY` | `dev-only-not-a-real-secret` | Flask session cookies |

`.env` and `.env.example` are both committed here, so keep anything genuinely
secret out of both — the checked-in values are throwaway.

## The database

```
sources    id, slug (unique), name
articles   id, source_id -> sources.id (cascade), url (unique), title,
           description, content, image_url, author, published_at
```

Two revisions, `759161cd8fb3` → `b773fddbe615` (head).

```bash
uv run alembic current            # where the database is
uv run alembic history            # the chain
uv run alembic upgrade head
uv run alembic downgrade -1

uv run alembic revision --autogenerate -m "what changed"   # then READ the file
```
